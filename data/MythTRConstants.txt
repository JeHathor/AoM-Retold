//==============================================================================
// AI "plan name" plan constants: explanation.
//==============================================================================
Legend: RO = Read Only, AC = Auto created, Max = maximum number of them you can allocate (-1 infinite).
These constants are what is called a variableIndex in the related AI syscalls.
These constants are used to set data on plans. Example: cBuildPlanBuildingTypeID on a build plan sets what building it should build.
Via these values you can control what a plan will do, it's mostly not advised to change these while a plan is underway unless you know what the consequences are.
If a value is not auto created then any syscall trying to manipulate it will automatically create the variable.
Attention: these numbers all start from 0 and then count up, meaning they can accidentally be used for a wrong plan type.
There is thus no guard against accidentally using cBuildPlanBuildingTypeID on an attack plan. And if the corresponding variable
at that index for the attack is also of the type int you wouldn't get an error either.

Another mechanic that goes hand in hand with the variableIndex is the valueIndex that can also be found on the related AI syscalls.
Each variableIndex has a number of values that can be associated with it, mostly it's just 1 though.
For example if you want to set 3 cDefendPlanTargetUnitTypes you need to do the following:
1. Call aiPlanSetNumberVariableValues with 3 for numberValues. (the default number allocated is 1, so it needs to be increased)
2. Call aiPlanSetVariableInt 3 times with variableValue 0/1/2.

If you want to keep your own set of data attached to a plan you can use the same kinds of syscalls as mentioned above but with the word User in them.
Those allow you to create any variable with any name/type for any plan and store information in there on a plan by plan basis.
